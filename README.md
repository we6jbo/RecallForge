# RecallForge v0.3.9.1

Adds scrollable tabs, copyable Publishing Results from Vibe-produced JSON, refresh, and opt-in Finalized guidance. Finalized waits until **both** 10 minutes and 25 confirmed answers. Private question content and Moltbook queue are not included. Vibe saves original drafts privately at `~/.oct9-recallforge-cache/unified-vibe/publishing-results.json`. Social posts remain pending without a real blog URL. Existing Pi stays unchanged.

## v0.2.8 — optional KinMap historical rotation
Settings now has opt-in KinMap family posting, research and rotation switches. Disabled by default. On Preparing the single Vibe session, generated instructions read `/var/lib/kinmap/kinmap_state.json` read-only, prefer relationship records from an authoritative KinMap tree, and keep private rotation state at `~/.local/state/recallforge/moltbook/kin_rotation.json`. KinMap layout positions alone are not evidence of relationships. Every Moltbook post or reply requires approval and private people must be excluded. No actual posts are made by the Qt GUI or installer.

## v0.2.9 publishing history
Publishing Results includes separate persistent completion checkboxes for blog, Facebook, LinkedIn, and Cowles Mountain speaking. Private records are stored under ~/.local/state/recallforge/publishing-history.json; approved drafts are never silently discarded. Vibe instructions check the ledger for duplicates and ask for a real blog URL before drafting missing social copy. The private question collection and credentials never belong in this source tree.

## v0.3.1: optional publishing help, automatically used when needed
The unified Vibe launcher and its instructions now discover `~/.local/state/recallforge/help/RecallForge-Publishing-Help-Library.json` (or the Markdown fallback) automatically. The library is only used for a fresh topic when actual mistakes, previously approved material, and saved history cannot yield suitable new study content. Vibe must check publishing history and avoid near-duplicates, preserve approval workflows and publish only after explicit approval. Social posts stay pending until the actual published URL is supplied. No manual Vibe reminder is necessary after opening **Vibe Workspace > Prepare one Vibe session**.

The help library is private local content and is not copied into the public source ZIP or uploaded to the Pi.

## v0.3.1 unified workflow and status icon
The legacy Web Companion tab is clearly deprecated and its outdated launcher is no longer generated or invoked by that tab. Use Vibe Workspace for original study guides and owner-approved remote updates. The unified launcher is regenerated when missing after reboot. The upper-left icon is gated by MD5 d41d8cd98f00b204e9800998ecf8427e of `/opt/z/z.txt`; if matching it displays three bats only when the private `workflow-status.json` reports six explicitly confirmed milestones for the current cycle, otherwise a pumpkin. A missing or corrupt status never claims completion. The application never modifies the checksum gate file or sends posts.


## v0.3.2: pre-Vibe Tailscale check and correction

Before entering Vibe, the unified launcher runs the owner-only `~/.local/state/recallforge/vibe-preflight.sh` generated by the installer. It checks SSH once with an 8-second connect timeout, captures any newly issued Tailscale authentication URL, opens only a validated `https://login.tailscale.com/a/...` URL in Chrome when available, and records the status in `~/.oct9-recallforge-cache/unified-vibe/preflight-status.md`. Authentication remains a user-controlled browser step. The launcher always proceeds to Vibe even when SSH fails. After a successful SSH check, no browser prompt is launched. An incomplete check is not retried in the same preflight invocation.

The Vibe instructions directly tell it to read `phone_post_o.md` and preflight-status.md, respecting both even after regenerated instructions. This is a local workflow fix; no Pi content, private backend or Moltbook record is modified by the installer.

## v0.3.3 family walk and deployment reconciliation
The unified Vibe workflow now follows a stateful, evidence-grounded family graph walk. Lester is only the initial seed, and blocked/private people may be traversed internally without appearing in public outputs. The walk never advances after unverified posts, preserves the private tracker, and refuses to make up relationship edges. For Web Companion, the Vibe instructions reconcile the current remote checksum, locally recorded manifest, and approved guide before proposing a scoped update; no remote changes are automatic. Both enhancements are Vibe workflow instructions, NOT a built-in genealogical graph parser or direct SSH implementation in Qt.

Before Vibe generates Moltbook proposals, a local, read-only structural KinMap audit reports the number of explicit family relationship edges and whether a proper graph export is required. ## v0.3.7 — ResearchNodeNetwork relationship source
Vibe is directed to use the installed ResearchNodeNetwork private registry and contract for documented family relationships before declaring a family walk blocked. KinMap positions remain supplemental, never inferred as relationships. The walk advances only after an individually approved, verified genealogy-bearing post, never after a cyber-only post. ## v0.3.8 Learning Insights
New private, local Learning Insights tab. Captures only explicitly confirmed Incorrect results from GUI grading, aggregates concepts, counts and short tips. Stores no question text, answer keys, or selected answer wording. Existing testbank files and the Vibe publishing workflow are untouched. Legacy mistakes may not appear retroactively.

## v0.3.9 Testing, Release Gate, content concerns
Testing is the safe default in Settings; Vibe instructions isolate test previews and prohibit all remote writes in Testing Mode. Prepare one Vibe session after changing the mode. The first Release Gate tab displays private `~/.oct9-recallforge-cache/unified-vibe/release-milestones.json` evidence and only turns green with all 11 verified records. Green is NOT permission to publish automatically. A review-only language scanner/index lives in private state and is invoked by Vibe before approving public material. The scanner's keywords are cues for context review, not automatic moderation or evidence of harmful intent. No changes to private testbank or Pi at installation.
